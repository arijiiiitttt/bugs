# Online Academy: Every authenticated user is rejected

**Track:** Express API bug-fix &nbsp;|&nbsp; **Difficulty:** Easy &nbsp;|&nbsp; **Stack:** Node.js + Express (in-memory database)

## Overview

This is the backend of a **Online Academy** where users can discover, create and manage courses.

**Problem:** Logged-in users get 401 on every protected endpoint although they send the `x-user-id` header.

Your task is to find and fix the bug in the backend so that all tests pass.

## How to work

```bash
npm test -- 026             # run the tests of this problem (replace 026 by the problem number)
DEBUG=1 npm test -- 026     # also print server-side errors to the console
```

- Only edit files inside `src/`. Never edit the tests.
- The "database" is a plain in-memory object (`src/store.js`). The tests reset it before every test.
- Stuck? Open `HINT.md`. Done (or really stuck)? `solution/EXPLANATION.md` explains the bug, and `npm run solution -- 026` runs the tests against the reference solution.

## Expected API behaviour

### Authentication

Protected endpoints (`POST /api/courses`, `PUT /api/courses/:id`, `DELETE /api/courses/:id`, `GET /api/courses/mine`) read the `x-user-id` header.

| When | Status | Body |
|---|---|---|
| header missing | 401 | `{ "message": "Not authenticated" }` |
| header present but no such user (also for malformed ids) | 401 | `{ "message": "Not authenticated" }` |
| header belongs to an existing user | request continues, the user is available as `req.user` | |

Public endpoints (`GET /api/courses`, `GET /api/courses/:id`) never need the header.
