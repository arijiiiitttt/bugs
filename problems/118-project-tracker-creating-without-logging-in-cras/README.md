# Project Tracker: Creating without logging in crashes the server

**Track:** Express API bug-fix &nbsp;|&nbsp; **Difficulty:** Medium &nbsp;|&nbsp; **Stack:** Node.js + Express (in-memory database)

## Overview

This is the backend of a **Project Tracker** where users can discover, create and manage tasks.

**Problem:** POST /api/tasks without an `x-user-id` header answers 500 instead of 401.

Your task is to find and fix the bug in the backend so that all tests pass.

## How to work

```bash
npm test -- 118             # run the tests of this problem (replace 118 by the problem number)
DEBUG=1 npm test -- 118     # also print server-side errors to the console
```

- Only edit files inside `src/`. Never edit the tests.
- The "database" is a plain in-memory object (`src/store.js`). The tests reset it before every test.
- Stuck? Open `HINT.md`. Done (or really stuck)? `solution/EXPLANATION.md` explains the bug, and `npm run solution -- 118` runs the tests against the reference solution.

## Expected API behaviour

### Authentication

Protected endpoints (`POST /api/tasks`, `PUT /api/tasks/:id`, `DELETE /api/tasks/:id`, `GET /api/tasks/mine`) read the `x-user-id` header.

| When | Status | Body |
|---|---|---|
| header missing | 401 | `{ "message": "Not authenticated" }` |
| header present but no such user (also for malformed ids) | 401 | `{ "message": "Not authenticated" }` |
| header belongs to an existing user | request continues, the user is available as `req.user` | |

Public endpoints (`GET /api/tasks`, `GET /api/tasks/:id`) never need the header.
