# Library Catalog: Authenticated requests hang forever

**Track:** Express API bug-fix &nbsp;|&nbsp; **Difficulty:** Medium &nbsp;|&nbsp; **Stack:** Node.js + Express (in-memory database)

## Overview

This is the backend of a **Library Catalog** where users can discover, create and manage books.

**Problem:** Requests with a valid `x-user-id` never get a response (the client times out).

Your task is to find and fix the bug in the backend so that all tests pass.

## How to work

```bash
npm test -- 124             # run the tests of this problem (replace 124 by the problem number)
DEBUG=1 npm test -- 124     # also print server-side errors to the console
```

- Only edit files inside `src/`. Never edit the tests.
- The "database" is a plain in-memory object (`src/store.js`). The tests reset it before every test.
- Stuck? Open `HINT.md`. Done (or really stuck)? `solution/EXPLANATION.md` explains the bug, and `npm run solution -- 124` runs the tests against the reference solution.

## Expected API behaviour

### Authentication

Protected endpoints (`POST /api/books`, `PUT /api/books/:id`, `DELETE /api/books/:id`, `GET /api/books/mine`) read the `x-user-id` header.

| When | Status | Body |
|---|---|---|
| header missing | 401 | `{ "message": "Not authenticated" }` |
| header present but no such user (also for malformed ids) | 401 | `{ "message": "Not authenticated" }` |
| header belongs to an existing user | request continues, the user is available as `req.user` | |

Public endpoints (`GET /api/books`, `GET /api/books/:id`) never need the header.
